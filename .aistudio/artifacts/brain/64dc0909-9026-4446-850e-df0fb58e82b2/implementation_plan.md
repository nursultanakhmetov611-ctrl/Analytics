# План интеграции репозитория и выпуска версии в ветке Merey

Интеграция рабочей области с репозиторием `https://github.com/nursultanakhmetov611-ctrl/Analytics`, подготовка коммита всех текущих доработок системы «АРС Аналитик — Astana Railway Services», улучшение аналитического блока, интерактивных отчётов и справочников с последующей отправкой (push) в ветку `Merey` через GitHub Personal Access Token (PAT).

## User Review & Critical Decisions

> [!IMPORTANT]
> **Подтверждённые решения (на основе ваших ответов):**
> 1. **Действие с репозиторием:** Сохранить и зафиксировать (commit) текущие доработки из этой среды и отправить их в ветку `Merey`.
> 2. **Метод отправки:** Использование GitHub Personal Access Token (PAT) для прямой отправки `git push origin Merey`. При этом токен будет использован только в изолированной сессии push и исключён из коммитов и открытого кода.
> 3. **Функциональный фокус версии Merey:** Улучшение аналитики (прогноз темпов выпуска, выявление узких мест), отчётов (экспорт данных в CSV/табличном виде) и расширение модуля «Справочники АРС».
>
> [!NOTE]
> Перед выполнением команды `git push` потребуется предоставить ваш GitHub Personal Access Token (с правами `repo` на запись в репозиторий). Мы настроим git-конфигурацию локально, подготовим структурированный коммит, а саму команду push выполним безопасно сразу после ввода токена.

## 1. Overview & Core Concept

- **Что делает система:** Интеллектуальный ситуационный центр производственного отдела вагоноремонтного холдинга ТОО «Astana Railway Services» за 2026 год, объединяющий оперативный мониторинг 4 вагоноремонтных депо (АВРД, КВРД, БВРД, УВРД), пономерную дислокацию вагонов, баланс колёсных пар (КП), суточный выпуск/подачу, матрицу причин простоев и настраиваемые справочники с ролевым доступом.
- **Целевая аудитория:** Главные инженеры депо, технологи, начальники производственно-диспетчерского отдела (ПДО), руководство холдинга в Астане.
- **Ключевая ценность версии Merey:** Полная синхронизация кодовой базы с удалённым репозиторием GitHub в ветке `Merey`, консолидированный аналитический блок с прогнозированием закрытия месячного плана, детализированные таблицы с экспортом и валидируемые производственные справочники.

## 2. User Experience & Visual Design

В соответствии с дизайн-системой корпоративных аналитических панелей (SaaS & Dashboards):

- **Атмосфера и цветовая гамма:**
  - Строгий индустриальный нейтральный фон (`bg-slate-50` / `bg-white`).
  - Тёмно-графитовые структурные элементы (`#0F172A`, `#1E293B`) с чёткими тонкими разделителями (`border-slate-200`).
  - Строгая семантическая палитра индикаторов: изумрудный (`#16A34A` — выполнение плана $\ge 100\%$, штатный оборот), янтарный (`#D97706` — отставание от темпа, неоконченный ремонт), пунцовый (`#DC2626` — простой по браку КП/автосцепки).
  - Никаких градиентных «капсул-пилюль» и декоративных мигающих точек — строгая моноширинная цифровая типографика (`font-mono tabular-nums`).
- **Типографика:**
  - Заголовки и экранные разделы: `Manrope` / `Plus Jakarta Sans`.
  - Табличные данные, номера вагонов (8-значные коды), даты и расчётные метрики: `JetBrains Mono` с `tabular-nums`.
- **Навигация и ключевые экраны:**
  - **Верхний бар (Top Bar Contract):** Логотип и холдинг слева, быстрый переключатель вкладок (`Аналитик`, `Сводка планов`, `Дислокация`, `Колёсные пары`, `Суточный выпуск`) по центру, профиль пользователя, журнал аудита и кнопка «Справочники АРС» справа.
  - **Улучшенный аналитический блок:** Сводные карточки ключевых показателей эффективности (KPI) с расчётом необходимого суточного темпа для ликвидации отставания от плана октября 2026 г., матрица узких мест по простоям.
  - **Экспорт отчётов:** Кнопка быстрого скачивания текущих отфильтрованных срезов дислокации и выполнения плана в формате CSV.
  - **Модуль справочников:** Табличное управление филиалами, заказчиками, причинами простоев и нормативами толщины обода КП с мгновенным поиском.

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Изоляция и чистота Git-репозитория**
  - *Подход:* Инициализация git в рабочей директории, добавление `.gitignore` для `node_modules`, `dist`, временных файлов и архивных дампов, подключение `origin` на `https://github.com/nursultanakhmetov611-ctrl/Analytics`, переключение на ветку `Merey`.
  - *Почему:* Обеспечивает точный и чистый коммит без мусорных файлов, сохраняя историю и структуру репозитория.
- **Решение 2: Безопасное использование Personal Access Token (PAT)**
  - *Подход:* PAT запрашивается у пользователя для разового пуша через URL аутентификации `https://<TOKEN>@github.com/...` и не сохраняется в кодовой базе или файлах `.env`.
  - *Почему:* Соответствие стандартам безопасности данных и исключение утечки персональных ключей на GitHub.
- **Решение 3: Развитие аналитического ядра (utils/arsEngine.ts)**
  - *Подход:* Добавление аналитических функций расчёта суточного дефицита (Run-Rate / Required Daily Pace), агрегации простоев по видам узлов (КП, автосцепка, подача со станции) и генерации структурированных CSV-отчётов.
  - *Почему:* Повышает практическую пользу системы для производственного отдела холдинга АРС.

### Этапы реализации:
1. **Этап 1: Доработка функционала версии Merey в коде**
   - Улучшение аналитики: расчёт требуемого суточного темпа выпуска до конца месяца (октябрь 2026), группировка узких мест.
   - Добавление экспорта данных сводки планов и дислокации в CSV с поддержкой кириллицы (BOM).
   - Обновление справочников АРС и типизации.
   - Проверка сборки и линтинга (`compile_applet` и `lint_applet`).
2. **Этап 2: Инициализация и настройка Git**
   - Инициализация `git init` в директории приложения.
   - Настройка удалённого репозитория `origin` на `https://github.com/nursultanakhmetov611-ctrl/Analytics`.
   - Привязка к ветке `Merey`.
   - Создание содержательного коммита: `feat(merey): enhance analytics, daily run-rate forecasting, CSV exports, and updated ARS references`.
3. **Этап 3: Отправка изменений (git push)**
   - Получение от вас GitHub PAT и выполнение команды `git push origin Merey`.
   - Подтверждение успешной отправки в ветку `Merey` на GitHub.
